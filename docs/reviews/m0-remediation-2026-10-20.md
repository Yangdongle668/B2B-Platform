## 1. 已整改的设计冲突

| 问题 | 当前统一行为 | 设计状态 / 实现验收 |
|---|---|---|
| DR-01 审校字段归属 | 唯一持久策略在cnt_content，读取模型投影；可信拥有者按内容version设置；父先子后锁；策略变更递增各语言共同版本并取消旧审批 | 框架4.4.16/4.10.7、content/page/translation及ADR-024已对齐；跨语言并发和晚到事件测试待M0-07 |
| DR-02 媒体删除 | 普通软删保留对象30天；恢复锁验状态和purge标记；到期清理先同事务创建持久任务及purge_job_id，提交后幂等删对象；force不绕过引用 | 框架4.10.1、media5.1.1及ADR-019对齐；对象存储故障、保存/删除/恢复竞态待M0-07 |
| DR-03 下载提交 | 仅ACCEPT非测试签发；提交、固定download_grant及通知发件箱同事务。模板/签名/入队失败全部回滚，提交前不得暴露URL；幂等返回首次结果且不续期 | 框架4.4/4.10.6、form/media/notification及ADR-023对齐；真实服务和故障矩阵待M0工程验收 |
| DR-04 双重规则 | 翻译在外部计算前捕获并持久化目标version，锁验后依次apply，拥有者最后且仅一次增共同版本；源事务同步媒体引用；动态响应共享freshUntil预算，无长stale | 完整接口、事件表、示例及ADR-003/012/019/020/024同步；缓存/任务恢复/所有provider适配待M0-07 |

“设计已整改”不等于原正式评审的全部关闭判据已经满足：testkit和真实业务并发用例尚不存在，DR-01～04保留实现验收关卡。新增跨模块契约仍只在平台框架定义；ADR说明理由，不复制一套签名。原正式评审和证据快照保留，后续结论在本报告追踪。

## 2. 数据库与静态验证

119个原有CREATE块保持不变，3个新增ALTER块追加在media/form/translation拥有者文档：

| 拥有者 | 新增字段 | 作用 |
|---|---|---|
| media | gated_form_key、download_gate_version、purge_job_id | 门控上下文、票据撤销及已提交物理清理义务 |
| form | download_grant JSON及CHECK | 固定首个下载结果，幂等重放不续期；只有ACCEPT非测试下载提交可存grant |
| translation | expected_target_version及CHECK | 外部计算前的目标版本，旧结果不能通过刷新版本覆盖新草稿 |

在MySQL8.4.11新空库中按外键顺序执行119个CREATE及3个ALTER，外键检查开启，均成功，仍是119张表；information_schema确认审校策略列只在cnt_content。字段追加目前是V002迁移设计，尚非可部署的业务Flyway升级脚本；首次启用/升级顺序仍由M0-11实现。

17个描述符、96权限、36组件、234后台端点设计及238验收项通过静态核对；依赖DAG、L2方向、当前文件链接与废弃规则检查通过。它们是文档覆盖数，不是已实现的功能或执行过的238个测试。

## 3. 已运行的最小兼容性组合

| 组件 | 本次真实版本 |
|---|---|
| JDK / Maven | Temurin25.0.4.1 / Maven3.9.16 |
| Boot / Modulith | 4.0.8 / 2.0.8 |
| MyBatis-Plus | 3.5.17，Boot4 starter与jsqlparser |
| Flyway / MySQL | 11.14.1（Boot管理） / 8.4.11 |
| Node / Nuxt / Vue | 24.19.0 / 4.6.2 / 3.5.44 |
| Nuxt Image | 2.2.0，自定义provider扩展点 |

后端7个测试通过：单库Flyway建表、跨站读取隔离、跨站更新拒绝、提交后事件投递、回滚时无业务行/事件登记、失败监听持久化并显式重投、模块边界及虚拟线程（其中Flyway与读取为同一测试）。故意抛出的监听失败是重试测试输入，不是未处理的测试失败。

前端类型检查和生产构建通过；HTTP直接读取证实SSR输出，自定义图片provider返回可加载图片。浏览器在1440/768/390三个视口验证：屏外组件尚未水合，滚动可见后水合，两次点击计数为2；没有页面错误或水合警告。这是功能兼容验证，不能据此宣称Tesla视觉稿完成。

原型发现并修复两处真实集成差异：Modulith2.0.8内置MySQL表物理名为大写EVENT_PUBLICATION，Linux不能按小写查询；Nuxt Image2自定义provider默认导出需为setup函数。文档和夹具已同步，不修改框架内置schema。

## 4. 下一批开发安排

1. **M0-07先验证媒体锁与翻译目标版本**：使用本批规则构建双事务时序，验证保存/删除、恢复/purge、策略变更/晚到翻译；补下载失败矩阵及固定grant重放。为每项记录输入、受控锁顺序和最终持久状态。
2. **继续M0-07缓存原型**：真实Redis代次、旧loader回填、重启/CDN失败持久重试、各层freshUntil总预算；不能仅用内存替身证明。
3. **M0-08搜索原型**：先写容量与延迟验收阈值，再实测不可变代次全量复制成本、源事务锁开销、迟到请求/worker、日志清理；DR-05仍阻塞整体契约冻结。
4. **补M0-06完整版本门禁**：Security/Session、HTTP客户端、MyBatis豁免表、模块独立Flyway history/升级、Scenario API及Nuxt主题/变体。现在只验证候选子集，ADR-011仍Proposed。
5. 上述证据进入M0-09契约RC复审，再按M0-10～14建立业务工程/core/testkit/CI并验收G0。M1产品→询盘闭环之后才进入M2～M4；产品页/询盘的Tesla视觉稿可提前准备。

DR-05、DR-06尚未关闭；DR-07视觉稿、DR-08阶段依赖与DR-09目录/治理按原计划跟踪。未自动签署人工评审，未把任何Proposed改为Accepted，未发布生产环境或推送本批变更。
