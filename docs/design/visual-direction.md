## 1. 视觉目标与适用边界

以大幅产品与应用影像建立第一印象，用简洁的文字、充足留白和稳定栅格组织信息。页面应让采购方能依次完成“理解产品价值 → 核对参数与资质 → 获取资料 → 提交询盘”。

| 维度 | 项目采用方式 |
|---|---|
| 首屏 | 一幅有明确主体的产品/应用图；一个主标题、一句简短价值说明、一主一次行动入口 |
| 页面节奏 | 首屏影像 → 关键规格 → 优势图文 → 应用/案例 → 文档/FAQ → 询盘；白、浅灰和必要的深色区段形成节奏 |
| 排版 | 大标题、有限字重、明确层级；中文保留自然字距，长语言可换行，不为追求同一行强行缩小字号 |
| 色彩 | 黑白灰为主体；品牌色在链接、焦点和少量强调处出现；表单错误/成功另用语义色 |
| 控件 | 规整按钮、细边框、低圆角、轻或无阴影；一组行动入口只有一个视觉主按钮 |
| 动效 | 短距离淡入、菜单和状态切换；尊重减弱动画，正常滚动无需等待动画才能阅读 |
| 内容密度 | 营销区段疏朗；规格表、筛选、文档和询盘保持足够的信息密度与可扫描性 |
| 素材 | 展示企业自己的产品、工厂、应用及案例；没有材料时设计稿标明素材需求，不虚构认证、客户或参数 |

默认使用普通纵向滚动。长规格、法律文本和表单支持自然阅读；全屏影像是可选择的首屏表达，不强制每个区段占满一屏或吸附滚动。

## 2. 视觉参数与 Token 映射

以下是项目建议初值。实施时先在 `frontend/packages/design-tokens` 的 primitive/semantic/component 三层统一定义，再由主题引用；表内路径是待落地的 Token 设计，不表示仓库已经存在同名文件。组件、布局数据和模块业务代码不得直接散落这些数值。

### 2.1 色彩

| 语义 | 建议初值 | 用途 |
|---|---|---|
| `color.surface.default` | #FFFFFF | 主背景、表单和阅读区 |
| `color.surface.alt` | #F4F4F4 | 规格、卡片底色和交替区段 |
| `color.text.default` | #171A20 | 标题、正文和默认深色 CTA |
| `color.text.secondary` | #5C5E62 | 说明、辅助标签 |
| `color.text.inverse` | #FFFFFF | 深色背景与经过对比度校验的影像文字 |
| `color.border.control` | #76787C | 需要可辨认边界的输入控件 |
| `color.brand.primary` | #1F5FD1（初值） | 品牌链接与强调；已有品牌色可按白名单替换 |
| `color.focus.ring` | 引用品牌主色 | 键盘焦点，保留与深浅背景均可辨认的间隔/双层边界 |
| `button.primary.bg` | 引用默认深色文字语义色 | V1 默认深色实心按钮；影像深背景中使用反白变体 |
| `button.secondary.bg` | 引用默认背景语义色 | 次按钮；边框及文字清晰可见 |

本表只规定默认主题。主题允许覆盖 component 层，不要求所有主按钮都跟随品牌链接色；站点品牌覆盖仍受系统设计11.3的白名单与对比度校验约束。

正文/按钮文字对比度至少4.5:1，控件与焦点边界满足适用的非文本对比度要求。图片上的文字必须针对实际素材检查，必要时使用稳定的深色遮罩或独立实底文案区，不能只靠文字阴影。

### 2.2 字体、栅格与尺度

| 类别 | 桌面基线 | 移动基线与边界 |
|---|---|---|
| 字体 | 拉丁默认 Inter，自托管 Latin/Latin Extended，`font-display: swap`；中文按系统字体栈 | 不下载中文 Web 字体，字体加载失败可读且不造成明显布局跳变 |
| 一级标题 | 48–64px 的流式字号，字重500–600 | 32–40px；长标题自然换行，不裁掉关键信息 |
| 二级标题 | 32–40px | 24–32px |
| 正文 | 16–18px，行高约1.6 | 正文及输入文字不小于16px，辅助文字不小于14px |
| 阅读区 | 最大约760px；正文左对齐 | 随容器宽度，保留左右安全边距 |
| 内容容器 | 最大约1280px，左右约48–64px外边距 | 左右约20px；360px宽度仍可用 |
| 栅格 | 12列；列表默认3列，空间充足时由既有变体支持4列 | 平板2列，手机1列；不压缩产品关键参数来硬塞列数 |
| 区段间距 | 约96–128px | 约48–64px；紧凑规格区另用密度 Token |
| Header | 约72px高 | 约64px高，菜单和主入口可触达 |
| 按钮与输入 | 高度约48px，低圆角约4px | 触控目标默认至少44×44px；双CTA优先纵向排列 |
| 动效 | 常规状态切换约160–240ms | 减弱动画模式关闭非必要位移与视频自动播放 |

断点与编辑器预览沿用框架规定的1440/768/390三档；补测360px、短屏、横屏及200%文字缩放。预览尺寸不等于 CSS 断点值，实际 breakpoint Token 统一在 tokens 包定义。

## 3. 页面与信息结构

### 3.1 首页（PAGE/HOME）

```text
精简 Header：Logo｜产品｜应用/解决方案｜案例｜关于我们｜联系入口
──────────────────────────────────────────────────
产品或应用主影像
        主标题 / 一句价值说明
        [了解产品]  [获取方案]
──────────────────────────────────────────────────
关键能力或规格（最多3–4个真实指标）
产品系列 / 产品网格
优势图文 + 应用场景
客户案例 / 资质与制造能力（材料齐备后呈现）
FAQ + 简洁询盘入口
页脚：联系信息 / 法律页面 / Cookie 设置 / 语言入口
```

首屏可居中文字；后续参数和长文左对齐。首页主入口优先指向产品集合或对应方案/询盘表单，不要求访客先观看视频。

### 3.2 产品分类及分类落地页（TERM_PAGE）

顶部使用简洁标题、短说明及可选分类影像；下方产品图片、名称和关键参数组成稳定网格，卡片使用浅背景和少量装饰。筛选、排序、当前条件、清空条件与结果数量有独立位置。

筛选交互按 search 的M4切片交付：桌面侧栏/工具栏，移动端用可关闭的筛选面板；M4前展示发布态基础列表，不画出实际不可用的筛选能力。空结果给出清除条件入口，搜索服务故障与真正零结果有不同状态。

### 3.3 产品详情（PRODUCT）

首段为产品图集与型号/价值说明，保留产品名、关键规格及主CTA。页面继续按“技术参数 → 产品优势/应用 → 型号表（M4）→ 资料下载 → 相关产品/案例 → 询盘”展开；使用既有 `product-detail` 模板及插槽。

规格采用清晰表格，数值、单位、可选型号和差异容易比较。下载按钮显示文档类型和必要说明；留资资料走 form 的门控流程，不因视觉追求直接暴露私有文件URL。移动端宽表可在自身容器横向滚动，页面主体不能被撑出视口。

### 3.4 应用、案例与文章

应用/解决方案使用已有 TERM_PAGE 或 PAGE，配合图文、产品卡片和案例；不新增“解决方案”业务模块。案例强调问题、实施方案与有依据的结果，影像与正文交替。文章采用舒适的阅读列、明确标题/日期/作者与少量关联内容；FAQ仍为可复用内容组件，不新增独立FAQ路由要求。

### 3.5 询盘、下载与联系

首次表单只要求完成该业务必要的字段；字段按已配置表单定义呈现。标签始终可见，必填说明、字段错误、提交进度、成功和服务不可用状态明确；不能仅用 placeholder 代替标签。提交中保留输入，失败后允许重试，后端继续使用幂等键。

主CTA围绕“获取方案”“提交询盘”“下载规格书”。同意营销为单独、默认未勾选的选项。隐私告知、实际展示版本及拒绝/待复核行为按 form/inquiry 要求，不由主题自行更改。

### 3.6 搜索、法律页与异常页

搜索页沿用同一 Header/字体/按钮，但内容区以输入、筛选和结果为中心。法律页使用安静的单列阅读版式。404、410、503分别给出相应文案与可行下一步；503不被主题伪装为产品不存在。普通预览/画布显示预览状态，不把它放入公开缓存。

## 4. 导航与响应式交互

| 区域 | 要求 |
|---|---|
| 主导航 | 一级入口精简，产品较多时使用分组菜单；产品/应用分类来自现有 navigation 和发布态内容，不硬编码企业目录 |
| Header变体 | 建议 `overlay` 与 `solid`：首页影像区可使用 overlay，进入浅背景内容切换 solid；产品列表、规格和阅读页默认 solid |
| 键盘与触控 | 菜单可点击与键盘打开、Esc关闭、焦点可见；不能依赖 hover 才能访问；手机菜单有名称、展开状态和返回入口 |
| 移动CTA | 如产品详情启用底部询盘入口，考虑安全区、键盘和Cookie横幅；不得同时叠加遮挡规格/提交按钮的多个浮层 |
| 表格与面板 | 横向滚动限制在表格区域；筛选面板有明确“应用/清空/关闭”，关闭后焦点回到触发按钮 |
| 图片适配 | hero配置桌面/移动裁切与焦点，保证产品主体可见；图片文字尽量由HTML承担，避免把标题烙在图片中 |
| 菜单缺项 | 目标在当前语言未发布时按 navigation 规则隐藏；主题不补一个看似可点的死链接 |
| Cookie区域 | 接受与拒绝同等显眼；颜色与主视觉一致，必要的法律告知仍清楚；不把拒绝按钮隐藏成低对比度链接 |

Header/Footer继续是主题固定区域，通过现有设置选择变体，不能改为页面编辑器自由拖拽区域。上述变体名是后续主题元数据的设计约定，不构成新的后端接口或组件类型。

## 5. 模块到视觉表现的映射

| 模块 | 前台表现要求 | 实现归属与约束 |
|---|---|---|
| page | 影像Hero、留白图文、克制的数字/CTA区段、易读法律页 | 现有 hero/rich-text/image-text/cta 等组件与模板；样式选择限Token/变体 |
| product | 大产品图、规整网格、易比较的规格/型号与下载区域 | product-gallery/product-grid/product-specification等；结构化参数优先可读 |
| navigation | 精简主导航、清楚的移动菜单和简洁页脚 | navigation提供资源，Header/Footer由主题实现 |
| article | 大封面与舒适阅读列，案例展示有依据的成果 | 既有文章、案例、faq组件；不改变内容类型和发布规则 |
| form / inquiry | 简洁字段、主次CTA、明确错误/成功反馈和可见告知 | 表单Schema与询价篮负责业务状态，主题只负责呈现 |
| graph | 低装饰的相关内容卡片，与产品/文章卡片视觉统一 | related数据源和related-content组件继续区分 |
| search | 明确条件、规整结果及可用的移动筛选 | M4交付；降级状态不因视觉处理而被隐藏 |
| tracking | 与全站一致的轻量Cookie横幅、同等可见的选择和退出入口 | 运行时UI，不注册成可拖拽布局组件；GPC规则保持有效 |
| delivery / seo | SSR首屏完整，页面标题/层级、状态和结构化数据准确 | 不用整屏动效延迟语义内容；没有数据时呈现真实状态 |

所有可翻译文字仍走文案键或翻译提供方。布局中的内容、媒体、分类和数据源仍为对象化引用；视觉设计不改变现有模块、快照、权限或跨模块契约。

## 6. 图片、动效与性能

默认首屏为静态高质量影像，通过现有 imgproxy/imageSources 生成 AVIF/WebP、srcset 与正确尺寸，减少布局偏移。首屏LCP图优先加载，下面的图延后；不能为了视觉效果一次预载全站大图。

视频首屏作为可选变体：有海报与静态替代，默认静音、可暂停；减弱动画/节省流量/资源失败时展示海报，营销或追踪服务的加载仍服从 consent。不要把视频播放作为主标题与CTA出现的前提。

正常滚动与键盘导航不被全页动画接管，固定区域、菜单和表单都保留焦点。页面仍满足系统设计1.5：移动LCP≤2.5s、INP≤200ms、CLS≤0.1、首屏gzip JS≤150KB；典型产品页移动Lighthouse Performance≥90、SEO=100、Accessibility≥95。

## 7. 后台 UI 的适用方式

后台继续是 Vue 3 + Element Plus，使用它自己的主题变量；不把前台Token直接注入Admin。可采用统一的中性配色、清晰间距、低装饰表格/表单与有层级的操作按钮，保留批量操作、密度、状态、错误与数据范围提示。

Tesla参考主要用于对外官网。内容编辑器的Admin外壳保持工作效率，iframe画布展示前台真实主题，实现同一视觉方向下的所见即所得。后台始终简体中文。

## 8. 设计交付与视觉验收

| 阶段 | 要交付的内容 | 完成判据 |
|---|---|---|
| 当前 | 方向、参数建议、页面结构与模块约束（本文） | 业主已指定参考；规范可供设计与实现使用，不冒充已完成设计稿 |
| M0/M1基础 | Token映射、Header/Footer、产品首屏/详情/基础列表的设计稿与主题基础 | 字体/素材/对比度可验证；使用现有框架与产品模板；不提前启用后续模块能力 |
| M2 | 首页/落地页、组件画廊、编辑器真实预览和导航完整稿 | 既有组件类型覆盖要求及每组件2–3变体按框架验收，三档预览一致 |
| M3/M4增强 | 法律页/同意、多语言长文本、留资及搜索/型号交互状态 | 按对应模块切片，不把仅有视觉占位当成已实现功能 |

后续视觉稿先覆盖：首页、产品分类、产品详情、询盘，以及后台产品编辑页/前台画布。每页给出1440/768/390三档与360px补测；至少包含默认、加载、空、错误、成功、焦点/键盘、长标题及长译文状态。

视觉验收清单：

- 用户无需执行JS即可获得首屏主要标题、产品信息、内链与结构化数据。
- 大图、标题、CTA层级清楚；规格、筛选、资料和表单在常规缩放及200%文字缩放下可用。
- 实际图像上的文字、焦点、输入边界和错误达到适用对比度；键盘可完整操作。
- 三档设备及短屏无非预期横向溢出，浮动CTA、Cookie面板与软键盘不相互遮挡。
- 中文、目标语言长文案与缺失语言遵守已定规则；图中文字不承担唯一信息。
- 减弱动画、无视频/图片加载失败仍能阅读并完成询盘。
- 画廊截图、axe、Lighthouse及业务E2E提供真实结果；本轮文档工作未执行这些运行检查。
