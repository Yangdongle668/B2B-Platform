## 当前文档范围

- 具体化描述符、依赖、服务/扩展点/端口、事务与事件语义，列出后台与公开接口的输入、并发、幂等、权限及审计要求。
- 保留全部已有 SQL DDL、模块分层、表前缀和停用属性；补齐状态机、站点过滤，明确无表的交付缓存及搜索索引结构。
- 补齐界面入口、36 个布局组件类型的模块归属、数据源注册 key、配置与异步任务、测试替身及每模块 14 条验收项（共238条）。组件属性仍由后续 component-schemas 实现并按系统设计校验。
- 用实际框架 Schema 校验 17 个描述符草案，并核对96个权限码、36个组件类型与234条后台端点设计；检查必填章节、命名、依赖环、权限和组件唯一性、事件与 ADR 引用及现有 Markdown 链接。应用、MySQL、浏览器和性能测试未执行；没有以文档校验替代应用测试。

## 审查结论与开工前事项

完整的逐模块改进、检查依据和未决项见 [模块需求设计复审总结](../reviews/module-design-review-2026-10-20.md)。本轮新增56条接口设计，补足68条专项故障/一致性验收，并修正资源聚合标识、保存版本、里程碑与旧章节引用。

仍有11个具体契约/一致性问题（不含M0前提），各模块第14章保留编号、负责人角色与截止阶段：

| 阶段 | 范围 | 需先统一的事项 |
|---|---|---|
| M1 | media | 合法的发布快照读取方向；异步引用与媒体删除的竞争窗口 |
| M2 | article、url、delivery | 作者头像资源收集通道；子树重算的当前 RouteHints 输入；缓存回填、失效和持久重试协议 |
| M3相关切片 | article、content、form、notification、graph、tracking | 作者资源通道、法律页审校标记、留资邮件调用方向、通知接收人权限、关系集合并发、追踪配置失效通道 |
| M4 | search | 索引写入顺序、重建增量屏障与 swap 崩溃恢复 |

M0仍需建立代码骨架、冻结契约、提供testkit及登记负责人。已由既有草稿事件/Collector解决的媒体上报问题不再要求重复增加MediaApi写方法；作者独立资源与媒体删除竞争分别保留具体问题。所有既有SQL代码块保持不变，本轮未执行MySQL或应用测试。
