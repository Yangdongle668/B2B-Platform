# ADR-025：独立站点资源的生命周期事件与翻译事件分离

## 背景

作者头像/追踪脚本变化可能没有可翻译文本变化，不能借翻译资源事件驱动引用和缓存生命周期。

## 决策

新增只含标识的 SiteResourceChangedEvent，article/tracking及url.pattern在原资源事务登记，由 delivery 可靠失效，url.pattern另唤醒content重算。补注册 article.author 翻译资源；媒体引用走同步登记，翻译事件只为实际文本变化生成。

完整签名、事务边界、失败恢复与适配器约束统一在[平台框架 4.10.2](../framework/platform-framework.md)登记。本 ADR 解释决策理由，不另建跨模块契约定义。问题映射和故障验收见[处理说明](../reviews/design-issue-resolution-2026-10-20.md)。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 本文方案 | 明确事实提交和派生状态的边界，可恢复、可测试 | 新增资源事件及总表登记；必须区分作者资料资源与已固化文章快照，不自动改历史发布内容。 | 提议采用，待评审 |
| 任意非文本变化也发布 TranslatableResourceChangedEvent | 初期改动较少 | 违背原事件语义，触发无效翻译；translation 被停用时还不能承担缓存可靠性。 | 不采用 |

## 后果

### 正面

- 将 ARTICLE-01、TRACKING-01 从笼统待定项整理为具体设计，保持业务模块只访问自己的表。
- 并发、重试和宕机结果可由数据库/端口行为验证，不以文档审查代替运行测试。

### 负面与代价

- 新增资源事件及总表登记；必须区分作者资料资源与已固化文章快照，不自动改历史发布内容。
- 新增契约、真实实现、替身及契约测试需同批实现；本仓库尚无代码骨架。

### 需要遵守的规则

| 规则 | 检查方式 |
|---|---|
| 只通过平台框架登记的契约协作；站点边界不变 | 架构负责人评审、ArchUnit、Modulith verify |
| 必须执行本方案的并发/故障时序 | 处理说明中的契约、集成与故障注入用例 |
| ADR 不自动获得 Accepted 状态 | 按 [ADR 流程](README.md)及框架 4.9 评审；此轮仅起草方案 |
