## 背景

- 非功能需求（1.5）：HTML TTFB 在 CDN 命中 / 未命中时 ≤ 200 ms / ≤ 800 ms；Delivery API P95 在缓存命中 / 未命中时 ≤ 30 ms / ≤ 300 ms；**发布后前台可见（含缓存失效）≤ 60 s**；前台可用性 99.9%，后端故障时 CDN 继续提供过期缓存。
- 规模（A4）：单站 1 万产品 × 最多 10 种语言、5 千篇文章，HTML 页面数量很大，不能每次发布都清除整站缓存。
- 快照只包含本内容自身的数据，对其他内容、媒体、分类只保存 ID，读取时解析（6.4、ADR-004）。因此一个页面的渲染结果依赖许多其他对象：某个产品改名后，所有以卡片或链接形式展示它的页面都要更新。V1.0 按页面失效，粒度过粗，无法找出这些页面（0.2 第 11 项）。
- 发布后的处理全部在事务提交后异步执行，并且至少一次投递（4.4、ADR-003）。
- 站点是最高隔离单位，缓存也要按站点隔离（5.3、ADR-009）。
- CDN 由业主自行选择与部署（32 章 Q3），但必须支持按 Cache-Tag / Surrogate-Key 清除（2.4）。
- V1.3：目标语言的译文由 AI 异步生成后发布；站点资源（菜单、界面文案等）的译文保存后即生效（5.7）。前台渲染时不调用 AI（21.7）。

## 决策

1. **缓存分层**（23.1）：HTML 与 Delivery 结果只在 **CDN 与后端 Redis 两级**缓存；**Nuxt 层不缓存 HTML**，保持无状态。

| 层 | 内容 | 失效方式 |
|---|---|---|
| 浏览器 | 带哈希的静态资源（1 年，`immutable`）；HTML 使用 `max-age=0, must-revalidate`，每次向 CDN 确认 | 文件名变化 |
| CDN | HTML、图片、sitemap | Cache-Tag 清除 + TTL + stale-while-revalidate |
| Nuxt | 只缓存站点引导数据（进程内，≤ 60 秒） | TTL |
| Redis | Delivery 结果、站点引导数据、路由、权限、设置、sitemap | 标签索引（tag → 缓存键集合）清除 |
| 应用内存 | 扩展点注册表、Schema、域名到站点的映射 | Redis Pub/Sub 广播 |

2. **缓存标签**（23.2）：全部带站点前缀 `s{site}`。

| 标签 | 含义 |
|---|---|
| `s{site}` | 站点全部 |
| `s{site}:c:{contentId}` | 某内容（作为页面主体，或以卡片、链接形式出现） |
| `s{site}:t:{termId}` / `s{site}:m:{mediaId}` | 分类项 / 媒体 |
| `s{site}:g:{contentId}` | 某内容的关系列表 |
| `s{site}:list:{type}` | 某类型的列表（有新内容加入时失效） |
| `s{site}:nav` / `s{site}:settings` / `s{site}:sitemap` | 导航 / 站点设置与主题 / sitemap |

3. **标签由 delivery 生成**：delivery 为页面主体、所有卡片与引用添加标签；数据源的 `resolve()` 返回结果时一并返回缓存标签（10.5）。标签放在 `resolve` 响应的 `cache.tags` 中（24.4），Nuxt 原样输出为 `Cache-Tag` 响应头（21.2）。单个响应的标签超过 200 个时，把卡片标签合并为 `list:{type}`。
4. **事件驱动失效**（23.3）：delivery 订阅内容、分类、媒体、导航、站点设置、关系、路由、模块启停以及 `TranslationCompletedEvent` 等事件（4.3），在事务提交后异步执行 `CacheInvalidator`：计算标签 → 通过 Redis 标签索引删除 Delivery 结果 → 调用 CDN 按标签清除接口（2 秒去抖合并，失败重试）。导航或站点设置变化清除 `nav` / `settings`，相当于清除整站 HTML，频率低，可以接受。
5. **CDN 缓存策略**（21.3）：内容页 `s-maxage=86400, stale-while-revalidate=604800, stale-if-error=604800`；站内搜索与 404 为 `s-maxage=60`；sitemap、robots 为 `s-maxage=3600` + Cache-Tag；预览与编辑器 `no-store`；5xx 不缓存。不使用 SSG。
6. **防击穿与故障**：CDN 使用 stale-while-revalidate；Delivery 对同一缓存键用 Redis 锁合并并发回源（23.3）。Delivery 不可用时由 `stale-if-error` 提供旧页面；没有缓存时返回 503 + `Retry-After`，绝不返回 404（21.5）。
7. **缓存的 HTML 与访客无关**：访客地区、同意状态不写入缓存的 HTML，也不按地区区分缓存，地区由不缓存的轻量请求获取（20.2）；图片在 URL 中显式指定格式，不按 `Vary: Accept` 区分（12.3）。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 按 URL / 路径清除 CDN（V1.0） | 所有 CDN 都支持 | 找不到以卡片、链接形式引用某内容的页面，只能整站清除或等待过期 | 不采用 |
| 只靠短 TTL，不主动清除 | 实现简单 | 新鲜度与回源压力无法兼顾，达不到“发布后 60 秒可见”或命中率要求 | 不采用（TTL 只作兜底） |
| 每次发布清除整站 | 不需要计算标签 | 页面数量大，命中率崩溃，源站压力集中 | 不采用（只用于导航与站点设置变化） |
| Nuxt 层缓存 HTML（进程内或 Redis） | 减少渲染 | Nuxt 变为有状态；多了一层需要失效的缓存，排查困难 | 不采用 |
| 构建时生成静态页面（SSG） | 运行时开销最小 | 发布需要重新构建，与“发布后 60 秒可见”冲突 | 不采用 |
| CDN + Redis 两级，按 Cache Tag 精确失效 | 精确、快速；页面只依赖快照与 ID 引用也能保持新鲜 | 标签必须计算完整；CDN 必须支持按标签清除 | 采用 |

## 后果

### 正面

- 发布、改名、换图等变化只清除受影响的页面，前台在 60 秒内可见，其余页面保持命中。
- 快照“只存 ID、读取时解析”的模型可以成立：被引用对象变化时不必重新发布引用方。
- Nuxt 无状态，可以随意扩缩；后端故障时 CDN 继续提供旧页面，不会返回 404。

### 负面与代价

- CDN 必须支持按 Cache-Tag / Surrogate-Key 清除，限制了业主的 CDN 选择范围（2.4）。
- 标签漏加会让页面最长在 `s-maxage`（24 小时）内显示旧数据，问题不易察觉。
- 标签数量受响应头大小限制，超过 200 个时退化为 `list:{type}`，失效变粗。
- 导航、站点设置变化会清除整站 HTML，之后一段时间回源增加。
- 失效是异步的：事务提交到 CDN 清除完成之间有短暂的旧数据窗口。
- Redis 需要维护标签索引，增加写入与内存开销。

### 需要遵守的规则

| 规则 | 检查方式 |
|---|---|
| Delivery 结果与数据源必须为所有引用的内容、分类、媒体返回标签；新增数据源时一并返回标签 | 模块集成测试（28）；E2E 场景 S1、S2、S8：发布、改 slug、停产后，所有引用处按时更新 |
| 标签与 Redis 键都带站点前缀（`s{siteId}:…`），不得跨站点清除 | 单元测试；站点隔离测试（28） |
| Nuxt 不缓存 HTML，只输出 Delivery 返回的 `cache.tags` 与 21.3 规定的 `Cache-Control` | PR 评审 |
| 失效只由事件驱动，在事务提交后执行，监听器幂等（ADR-003） | 模块集成测试（Scenario API） |
| 缓存的 HTML 中不写入任何与访客相关的数据（地区、同意状态等） | PR 评审 |
| 故障时返回 503 + `Retry-After`，不返回 404 | PR 评审 |
| 缓存命中率与 Delivery 延迟纳入监控与告警 | 27.4 的指标与告警规则 |
| 新增标签类型时同步更新 23.2 | PR 评审 |
