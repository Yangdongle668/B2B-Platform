## 背景

前台页面分为两类，需求差别很大：

- **系统内容**：产品、文章、案例、分类落地页。按假设 A4，单站可达 1 万产品 × 多种语言。这些页面必须结构一致，SEO 结构（H1、面包屑、JSON-LD）有保证，主题升级时能批量生效，不能逐页维护（10.1）。
- **营销页**：首页、关于我们、落地页。运营需要不写代码自行搭建 Landing Page（Hero + 优势 + 产品网格 + 案例 + FAQ + 询盘表单），在三种设备尺寸下预览，并且只能使用设计系统内的组件与变体（1.3 S3）。

约束：

- 前台只读取发布态数据（快照与投影），永远不读取草稿（P4，6.4）。
- 页面与组件不得硬编码业务字段；组件通过 Schema 声明属性，通过数据源绑定数据（P5）。
- 前台样式只能来自 Design Token 与主题变体（P7）。
- “页面编辑器复杂度失控”是可能性与影响都为“高”的风险，对策是 V1 只做 Section 级编辑与预设变体、先做模板再做编辑器（31）；自由布局（像素级拖拽）不在 V1 范围（1.4）。
- V1.3：内容以简体中文（源语言）录入，其他语言由 AI 翻译生成（5.5）。布局的模型必须让目标语言的布局能自动跟随源语言，而不是每种语言各自维护一份。

## 决策

1. **两种渲染模式，共用同一套组件与布局文档格式**（10.1）：

| 模式 | 适用内容类型 | 布局来源 | 编辑方式 |
|---|---|---|---|
| 模板渲染 | PRODUCT、ARTICLE、CASE_STUDY、TERM_PAGE | 模板的固定区域 + 可编辑插槽 | 表单编辑业务字段；在插槽中放置组件 |
| 页面搭建 | PAGE（首页、关于我们、落地页；落地页 = PAGE + landing 模板） | 完整的布局文档 | 页面编辑器（画布方案见 ADR-007） |

   内容类型在 `ContentTypeDefinition` 中声明可用模板（`templates`）与是否允许插槽（`layoutSlots`）（6.2）。

2. **模板** = 主题中的 Nuxt 组件 + 共享包 `frontend/packages/component-schemas` 中的模板元数据（10.2）：
   - 区域分为**固定区域**（`fixed`：由模板渲染，读取快照中的业务数据）与**插槽**（`slot`：声明允许的组件 `allowed`、数量上限 `max`、默认内容 `default`）。
   - 固定区域的数据源（如相关内容的类型配比）在读取时解析，修改模板配置**不需要重新发布内容**。
   - 模板的 `label` 只写中文字符串（后台只用简体中文）。Delivery 与 Admin 通过 `TemplateProvider` 扩展点（page 模块实现）读取模板定义。

3. **布局文档**（10.3）：页面的全部 Section 与模板插槽中的组件，都保存在该本地化的布局文档中；发布时由 page 模块的 `PublishContributor` 写入快照的 `layout` 部分。

| 规则 | 内容 |
|---|---|
| 引用对象化 | 媒体、内容、分类、数据源只用 `$media`、`$content`、`$term`、`$source` 对象，**不保存 URL**；URL 在渲染时解析 |
| 样式只用 Token | `style` 的值只能是 Token 枚举（如 `paddingY: "xl"`），不允许任意 CSS |
| 有限嵌套 | 只有布局类组件（`columns`、`tabs`、`accordion-group`）可以通过具名 `children` 嵌套，最大深度 2 |
| 稳定 ID | Section 的 `id` 不变，用于编辑器选中、锚点与统计 |
| 按翻译模式生成 | 源语言布局由编辑维护；`AUTO` 模式下目标语言布局 = 源语言布局 + 译文，结构自动同步，只有 `x-translatable` 属性替换为译文；`MANUAL` 模式独立编辑（10.3、ADR-017） |

4. **组件**（10.4、10.5）：每个组件在 `component-schemas` 中有一份定义（`propsSchema`、变体列表、样式选项、`allowedIn`、迁移函数），`label` 只写中文字符串。属性用 `x-editor` 生成后台表单，用 `x-translatable` 标记是否提取为翻译单元（字符串与富文本默认 `true`；型号、代码、URL、枚举为 `false`）。业务数据只通过 `DataSourceProvider` 获取（`content-query`、`related`、`term-children`、`faq-by-context`、`search-query`）。变体由主题实现（11.2）。

5. **组件版本与迁移**（10.9）：属性发生破坏性变化时 `version + 1`，并在共享包中提供迁移函数 `(props, fromVersion) => props`；Admin 打开草稿时迁移，Nuxt 渲染旧快照时即时迁移，**旧内容无需重新发布**。删除组件时先标记 deprecated，保留渲染器，直到 `pg_component_usage` 显示已无已发布内容使用它。

6. **边界**：
   - Header / Footer 由主题实现，V1 不能用页面编辑器编辑（10.7）。
   - 全局区块是不可路由的 `GLOBAL_BLOCK` 内容，通过 `global-block` 组件按 key 引用，内部不能再引用全局区块（10.6）。
   - 法律页面使用 PAGE + `legal` 模板；Imprint 正文由站点资料中的法定信息自动生成；机器译文必须人工审校后发布（10.1、ADR-017）。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 所有内容都用页面编辑器搭建 | 最灵活 | 上万个产品页结构不一致，主题升级无法批量生效；H1、结构化数据等 SEO 结构难以保证；编辑工作量大 | 不采用：不适合大批量的系统内容 |
| 所有页面都用固定模板 | 实现最简单，结构一致 | 每个营销页都需要开发介入 | 不采用：不满足 S3 |
| 两种模式各用一套组件与文档格式 | 各自可以单独优化 | 组件重复实现；渲染器、编辑表单、迁移机制都要两套 | 不采用：违反“不重复实现已有组件” |
| 自由布局（像素级拖拽） | 运营自由度最高 | 复杂度高；破坏设计系统一致性、响应式与无障碍 | 不采用：风险 31，且不在 V1 范围（1.4） |
| 模板 + 插槽与页面搭建并存，共用组件、布局文档与渲染器 | 系统内容一致、可批量升级；营销页灵活；只有一套组件与渲染链路 | 需要维护模板元数据、组件 Schema 与迁移函数 | 采用 |

## 后果

### 正面

- 上万个系统内容页由模板保证结构一致；修改模板或推荐配比无需重新发布。
- 营销页由运营自主搭建，并且始终在设计系统的约束内。
- 只有一套组件、一套布局文档格式、一套渲染器（`LayoutRenderer`、`SectionRenderer`、`TemplateResolver`，21.1）；编辑表单由 Schema 自动生成（22.4）。
- 引用对象化：被引用对象改名、改路径后，引用方不需要重新发布；缓存标签可以从引用推导（6.4、23.2）。
- 结构与文本分离：AI 翻译只处理 `x-translatable` 属性，目标语言布局自动跟随源语言（ADR-017）。

### 负面与代价

- 需要同时维护模板元数据、组件 Schema、主题变体与迁移函数；共享 Schema 包被 Admin、Nuxt、后端三方使用，变更影响面大。
- 插槽的 `allowed` / `max` 限制了系统内容页的自由度，个性化需求只能通过新增组件或模板满足。
- 固定区域与 `$source` 在读取时解析，增加 Delivery 的计算量；依赖数据源限制（每个数据源最多 24 条、每页最多 10 个、单个解析超时 500 ms，10.5）与缓存（ADR-012）控制。
- `AUTO` 模式下目标语言不能单独调整布局结构；需要不同结构时只能切换为 `MANUAL`，此后不再自动同步，源语言更新后只标记 `OUTDATED`。

### 需要遵守的规则

| 规则 | 检查方式 |
|---|---|
| 组件不得硬编码业务字段；布局文档不得保存 URL，只用 `$content` / `$media` / `$term` / `$source`（附录 A 禁止 4） | PR 评审；后端保存时用 JSON Schema 校验布局文档 |
| 组件样式只用 Token 与主题变体 | Stylelint `declaration-strict-value`；ESLint 禁止带字面量的内联 `style`（11.4、29.3） |
| 组件 Schema 的破坏性变更必须提升版本并附迁移函数 | CI 中的 Schema 比对脚本（10.9、29.3） |
| 发布前校验布局文档符合 Schema | `PublishContributor.validate()`（6.3） |
| 新增前台组件同时提供 Schema、主题变体、组件画廊示例、无障碍检查、文案键，并正确设置 `x-translatable` | 29.2、29.6；Playwright 截图 `/__gallery` 视觉回归（28）；PR 评审 |
| 系统内容类型使用模板渲染，不改为页面搭建；偏离本决策先修订本 ADR | PR 评审（P8、29.5） |
| 删除组件先标记 deprecated，`pg_component_usage` 无已发布引用后才移除渲染器 | PR 评审 |
