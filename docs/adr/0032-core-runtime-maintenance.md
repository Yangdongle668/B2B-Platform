# ADR-032：Core节点租约与运行维护候选

| 项 | 内容 |
|---|---|
| 状态 | Proposed（待架构评审） |
| 日期 | 2026-10-21 |

## 背景

M0原有TSID实现仅接收外部分配的节点号，不能证明多实例安全；审计没有唯一保留期删除入口；本地缓存没有导出统计。框架5.7.5、5.11和5.13要求这些机制实际运行。

## 候选实现

候选实现的正数Java long为41位时间、10位节点、12位序列，纪元2020-01-01 UTC；尚未采用外部TSID库。复用`sys_lock`的`core:tsid-node:{n}`，无需新表。核心迁移完成后、首次声明式资源写入前取得节点；使用独立自动提交连接及数据库时间，5分钟租期、每分钟续租。节点号配置是优先候选，冲突时取其他空闲节点。每次发号检查单调时钟期限；续租失败永久关闭本实例发号和readiness，重新加入须重启。启动/续租核对应用与数据库时钟偏差不超过1秒；真实发号不提前到未来毫秒，回拨最多等待1秒，超过则拒绝。

关闭时停止发号，保留剩余租期作为隔离窗口，而非立即释放节点。这是对框架“释放租约”的明确细化：避免新进程时钟稍落后时重复上一实例的末尾编号。代价为快速频繁重启短时占用更多节点。不得以Redis锁保证ID唯一。

审计清理由`core.audit_retention`扩展交给现有ShedLock调度器，按UTC日期及`core.retention.auditDays`分批删除，单次工作有上限；普通写入服务不提供删除。增加框架既定的Actuator与Prometheus依赖，独立管理端口只暴露health/info/prometheus，本地只绑定回环。Caffeine统计绑定注册表；指标标签不包含用户、URL或内容ID。

## 验证与边界

真实MySQL测试覆盖并发实例节点不同、旧持有者续租失败后不能发号、关闭停止、审计边界与批次。可复用编号/加密/上下文套件同时跑正式实现及替身。自动化不能替代两名人工评审或本ADR签审。
