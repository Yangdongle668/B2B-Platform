# ADR-022：内容内核编排当前树的路由重算

|---|---|

## 背景

url 无合法反向读取页面树的调用方向，任务携带一次树快照不能处理二次移动及重启。

## 决策

content 拥有重算任务，以数据库事务互斥保护路由拓扑读取和批量更新。恢复时按当前 ContentTypeProvider.routeHints 重建父先子后顺序，generation 变化从当前树重启；url 仅执行已有路由写方法。

M0-07B原型补充：初始化互斥行用取得排他锁的upsert，替代INSERT IGNORE后升级锁；冷建行仍可能争用唯一索引末端间隙，因此站点初始化宜预建，数据库死锁/超时按整个事务回滚重试。游标定位在确定的父先子后序列中，不能按contentId数值过滤；任务去重包含generation和规范化语言集合，每批在互斥锁后复核工作租约。实测与限制见[路由协议复审](../reviews/m0-route-protocol-review-2026-10-20.md)。

完整签名、事务边界、失败恢复与适配器约束统一在[平台框架 4.10.5](../framework/platform-framework.md)登记。本 ADR 解释决策理由，不另建跨模块契约定义。问题映射和故障验收见[处理说明](../reviews/design-issue-resolution-2026-10-20.md)。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 本文方案 | 明确事实提交和派生状态的边界，可恢复、可测试 | 新增 core 数据库事务互斥能力及技术表；多批路径不是全站原子切换，冲突需可见暂停与重试。 | 提议采用，待评审 |
| url 调用 page 或长期复用任务携带的树 | 初期改动较少 | 前者违反分层，后者会把旧输入覆盖到新树。 | 不采用 |

## 后果

### 正面

- 将 URL-02 从笼统待定项整理为具体设计，保持业务模块只访问自己的表。
- 并发、重试和宕机结果可由数据库/端口行为验证，不以文档审查代替运行测试。

### 负面与代价

- 新增 core 数据库事务互斥能力及技术表；多批路径不是全站原子切换，冲突需可见暂停与重试。
- 新增契约、真实实现、替身及契约测试需同批实现；本仓库尚无代码骨架。

### 需要遵守的规则

| 规则 | 检查方式 |
|---|---|
| 只通过平台框架登记的契约协作；站点边界不变 | 架构负责人评审、ArchUnit、Modulith verify |
| 必须执行本方案的并发/故障时序 | 处理说明中的契约、集成与故障注入用例 |
| ADR 不自动获得 Accepted 状态 | 按 [ADR 流程](README.md)及框架 4.9 评审；此轮仅起草方案 |
