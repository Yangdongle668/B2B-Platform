## 背景

- 目标市场为欧盟、英国与北美（A2）。V1.2 确认“欧美为主”后，把 GDPR / UK GDPR / ePrivacy / CCPA 作为合规基线（0.5）：Cookie 事先同意、GPC、退出“出售 / 共享”、数据主体请求按法定时限处理（1.5）。
- 网站处理的个人数据：询盘联系人、IP、附件、后台用户、同意记录（26.8）；转化追踪使用 GA4、Google Ads、Meta Pixel 等第三方工具（20.1）。
- 很多问题需要法律判断（32 章 Q13）：GDPR 第 27 条欧盟代表与英国代表、询盘与下载留资的合法性基础、跨境传输（中国大陆员工访问、全球 CDN、美国服务商、Webhook 接收方）、CCPA 是否适用、加拿大的要求、同意记录保留期限；Imprint 所需的公司法定信息（Q14）。
- V1.3 业主确认：**Q13、Q14 等法务事项由业主自行负责**，系统设计中不下结论。V1.3 新增 AI 翻译，询盘翻译会把询盘留言发送给 AI 服务商（5.7）。
- 因此系统需要提供一套默认从严、可以按法务结论配置的能力。

## 决策

1. **Cookie 与追踪同意按访客地区确定模式**（20.2）：

| 地区 | 模式 |
|---|---|
| 欧洲经济区、英国、瑞士 | 明示同意（opt-in）：非必要 Cookie 事先同意后才加载；“全部拒绝”与“全部接受”同样显眼；类别不预先勾选；可随时撤回 |
| 美国 | 告知 + 可退出（站点可配置为明示同意）：识别 GPC，视为退出营销类 Cookie 与“出售 / 共享”；页脚可配置“Do Not Sell or Share My Personal Information”或“Your Privacy Choices”入口 |
| 加拿大 | 法务确认前按明示同意处理 |
| 其他地区 / 地区未知或判定失败 | 可配置 / 一律按明示同意处理 |

2. **同意的执行**（20.1–20.3）：访客地区由不缓存的轻量请求获取，不写入缓存的 HTML（ADR-012）；Consent Mode v2 的 `default` 在任何 Google 标签之前执行，欧洲经济区、英国、瑞士默认全部 `denied` 并采用基本模式；第三方脚本全部异步、延后加载，并按地区模式控制（明示同意地区获得对应类别的同意后加载；“告知 + 可退出”地区在访客未退出该类别时加载，收到 GPC 时不加载营销类）；统计服务商可切换为欧盟托管的 Matomo、Plausible，不写死 GA4。也可以关闭内置横幅改用第三方 CMP，此时同意记录与 GPC 由 CMP 负责。
3. **同意记录**：每次选择写入 `trk_consent_log`（同意 ID、动作、来源、同意文本版本、语言、横幅版式版本、各类别结果、地区、GPC 等，20.2），保留期默认 3 年（由法务确认）；同意 Cookie 有效期 6–12 个月；隐私政策或同意文本版本变化时重新征求。
4. **询盘与表单**（17.1、17.5、17.11）：采用“隐私告知 + 可选的营销同意”，**不强制勾选同意**；告知文本有版本号，询盘保存 `privacy_notice_version`；营销同意单独勾选、默认不勾选，保存 `marketing_consent` 与 `marketing_consent_at`；表单提交时保存 `gpc` 与 `opt_out_sale_share`。合法性基础（GDPR 第 6 条第 1 款 (b) 项或 (f) 项）由法务确认。V1 不在系统内发送营销邮件。
5. **数据主体请求**（17.11）：支持访问、更正、删除、可携带、反对、限制处理与 CCPA 的退出“出售 / 共享”；答复时限 GDPR / UK GDPR 1 个月内（必要时可延长两个月），CCPA 45 个日历日内（必要时再延长 45 天），具体以法务确认为准。后台工具由 platform-core 提供，通过 `PersonalDataProvider` 扩展点收集各模块的个人数据（3.7），需要 `system:dsr:manage` 权限（高危，强审计）；`sys_dsr_request` 记录请求、核验、处理与答复时间；核验通过前不导出、不删除；备份不做单条删除，记录删除台账，恢复后重新执行。
6. **数据最小化与保留期**（17.11、26.8、27.4）：

| 数据 | 保留 |
|---|---|
| REJECT 与垃圾询盘 | 30 天 |
| 已关闭的询盘、`frm_submission`、附件 | 按站点配置（默认 3 年）后匿名化，附件同步删除 |
| `ntf_message` | 发送成功后按较短期限（如 90 天）清理 |
| 原始 IP / 应用日志 | 30 天后置空 / 日志中 IP 截断，保留 30 天 |
| 审计日志 | 默认 1 年（可配置，26.5） |

7. **第三方与 AI 翻译**：自动翻译只向 AI 引擎发送公开的内容与站点资源；询盘翻译由销售手动触发，站点可以关闭，询盘译文不写入翻译记忆（5.7、26.8、ADR-017）；Webhook 载荷默认不含联系人信息（18）；视频采用外观占位，点击后才加载第三方（12.4）；图片输出时去除 EXIF（12.3）。
8. **上线前合规清单**（26.8）：处理活动记录（ROPA）；处理者清单（云厂商、CDN / WAF、Turnstile、邮件服务商、Sentry、统计工具、Webhook 接收方、AI 翻译服务商等，记录数据区域与传输依据）；与处理者签署 DPA；广告与社交平台的角色划分；每个站点的隐私政策、Cookie 政策、使用条款、Imprint（10.1、16.3）；数据泄露响应（GDPR / UK GDPR 第 33 条，知悉后 72 小时内通知监管机构，27.5）。
9. **职责划分**：系统提供上述能力与配置项，默认从严；Q13 中的法律判断、Q14 中的 Imprint 信息以及上线前合规清单中的法务内容由业主自行负责，确认后通过站点配置落实。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 所有地区统一采用明示同意 | 实现最简单，最严格 | 美国等地区的统计数据损失较大 | 不作为默认；站点可把美国配置为明示同意 |
| 只用第三方 CMP（Cookiebot、OneTrust） | 法规更新由厂商负责 | 增加费用与第三方处理者；同意记录与 GPC 交由 CMP 负责，需要逐项确认其满足 20.2 的要求 | 不作为默认；作为可选替代 |
| 询盘表单强制勾选同意 | 形式上“有同意” | 同意不是自由给出的；与合法性基础 (b) / (f) 的做法不符 | 不采用 |
| 写死 GA4 | 实现简单 | EU-US DPF 若被推翻，无法切换 | 不采用，统计服务商可切换 |
| Consent Mode 高级模式作为默认 | 获得同意前也能建模 | 同意前发送无 Cookie 请求，需要法务确认 | 不作为默认 |
| 默认从严、按地区确定模式、能力可配置 | 法务结论变化时只需改配置；同意与处理有据可查 | 实现与测试工作量较大 | 采用 |

## 后果

### 正面

- 默认满足最严格地区的要求；法务结论确定后通过配置调整，不需要改代码。
- 同意、隐私告知版本、数据主体请求都有记录，可以作为合规证明。
- 新模块通过 `PersonalDataProvider` 接入数据主体请求工具，个人数据不会遗漏在某个模块中。

### 负面与代价

- 明示同意地区的统计与广告转化数据减少。
- 同意记录、数据主体请求工具、保留期任务都是额外的开发工作（路线图 M3、M4）。
- 每个保存个人数据的模块都要实现 `PersonalDataProvider`，并维护保留期。
- 法务事项确认之前，部分行为（如加拿大访客、统计 Cookie 豁免）只能按从严处理。
- 备份中的个人数据无法单条删除，需要依靠删除台账。

### 需要遵守的规则

| 规则 | 检查方式 |
|---|---|
| 新增保存个人数据的表或字段：实现 `PersonalDataProvider`，定义保留期，更新个人信息清单与 ROPA | PR 评审；完成定义（29.6） |
| 非必要脚本只能通过 tracking 模块按同意类别加载；自定义脚本需要 `tracking:script:edit` 权限并记录审计 | 权限点 + 审计（26.2、26.5）；PR 评审 |
| Consent Mode `default` 在任何 Google 标签之前执行；地区未知按明示同意 | E2E 场景 S4（GA4 按同意状态收到转化事件，28） |
| 询盘表单不强制勾选同意；营销同意默认不勾选 | PR 评审 |
| 日志中 PII 脱敏、IP 截断；原始 IP 30 天后置空 | PR 评审；保留期任务 |
| 发送给 AI 引擎的只有公开内容与站点资源，询盘翻译除外（按需、可关闭、不进翻译记忆） | 翻译测试（28）；PR 评审 |
| Webhook 载荷默认不含联系人信息 | PR 评审 |
| 数据导出与数据主体请求的处理记录审计 | 审计（26.5） |
| 上线前完成合规清单；法务部分由业主确认 | 上线评审（26.8） |
| 改变本 ADR 的基线（如取消某地区的明示同意）需要新的 ADR | 29.5 |
