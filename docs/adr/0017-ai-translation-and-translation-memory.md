## 背景

- V1.2：其他语言由人工翻译，系统只做过期检测；机器翻译属于【V2+】，计划由 AI 模块通过 `TranslationProvider` 扩展点生成初稿。
- V1.3 业主确认（0.5）：前台先只显示简体中文；其他语言通过 **AI 引擎翻译**生成，**翻译一次并存储，相同原文第二次不再翻译**；AI 引擎默认使用 **OpenAI 通用（兼容）接口**。中文为源语言（ADR-005）。
- 规模（A4）：单站 1 万产品 × 最多 10 种语言；内容会反复修改，每次整篇重译既费钱又会冲掉人工修订。
- 质量风险：品牌名、型号、术语译错；法律页面（隐私政策、Cookie 政策、条款、Imprint）不能直接使用机器译文；Google 允许自动翻译，但要求对用户有帮助（5.8）。
- 约束：模块只通过 `platform-api` 中的契约协作（ADR-002）；发布后的处理在事务提交后异步执行（ADR-003）；**AI 引擎故障不能影响中文内容的发布**；前台只读快照，渲染时不调用 AI（P4、21.7）；不绑定某一家服务商。
- 销售需要阅读德语、法语等语言的询盘（S13）。

## 决策

1. **新增 translation 模块**（3.2）：L2 基础能力模块，表前缀 `trn_`，可停用（停用后不再自动翻译，已生成的译文保留），V1 范围（路线图 M3）。职责：翻译单元提取与回写的编排、翻译记忆、术语表、风格指南、引擎适配、翻译任务（实时与批量）、用量与成本统计、翻译中心。表：`trn_engine`、`trn_memory`、`trn_glossary_term`、`trn_style_guide`、`trn_job`、`trn_job_item`、`trn_usage_daily`（25.8）。
2. **翻译对象**（5.5）：内容（产品、文章、案例、FAQ、页面、分类落地页、全局区块）通过 `TranslatableContentProvider` 提取与回写；站点资源（菜单、表单、界面文案、属性名与选项、分类名、媒体 alt / 标题、客户邮件模板、站点资料文本、Cookie 横幅文案）通过 `TranslatableResourceProvider`（3.7）。图片、数值、型号、分类指派、关联关系、布局结构等非文本数据不翻译，直接沿用源语言。
3. **翻译模式与状态**（`cnt_localization`，5.5、6.1）：`translation_mode` 为 `SOURCE` / `AUTO`（目标语言默认：由源语言 + 翻译记忆生成，布局结构自动同步，人工只能按段修订）/ `MANUAL`（独立编辑，源语言更新后只标记 `OUTDATED`）；`translation_state` 为 `NONE` / `QUEUED` / `TRANSLATED` / `NEEDS_REVIEW` / `FAILED` / `OUTDATED`。
4. **翻译单元与翻译记忆**（5.6）：
   - 翻译单元：纯文本字段一个字段一个单元；富文本按块级节点拆分，行内标记转为编号占位标签（`<1>…</1>`），翻译后还原。单元带字段路径、格式（`TEXT` / `RICH_INLINE`）、可选长度上限、上下文说明。
   - 翻译记忆 `trn_memory` 的键为 `(source_locale, target_locale, source_hash, variant)`；`source_hash` = SHA-256(规范化原文)（NFC、去首尾空白、合并连续空白）；超长时另存 `max{N}` 变体。
   - **命中即复用，不调用 AI**；同一批次中重复的原文只翻译一次；不设过期。
   - 优先级 **`HUMAN` > `REVIEWED` > `MACHINE`**；人工修订写回翻译记忆；**机器翻译永远不覆盖 `HUMAN` / `REVIEWED` 条目**。
   - 同一站点内，内容与站点资源共用一个翻译记忆，常用词全站译法一致。
5. **翻译流程**（5.7）：

   ```text
   源语言发布（ContentPublishedEvent）→ translation 在事务提交后异步处理：
     为每个启用自动翻译的目标语言创建 trn_job → extract() 得到翻译单元 → 查翻译记忆
     → 未命中的单元去重后分批调用引擎（每批约 50 个单元或 token 上限）→ 校验 → 写入翻译记忆
     → apply() 写回目标语言草稿（非文本数据从源语言复制）
     → 按站点配置自动发布（默认）或进入审核；法律页面一律进入审核
     → TranslationCompletedEvent / TranslationFailedEvent
   ```

   - 自动发布由内容内核在收到 `TranslationCompletedEvent` 后执行，与人工发布同一套校验与流程，操作人记为 `system`（4.4、6.3）；任务执行期间源语言再次发布时，以新修订为准，旧任务作废。
   - 源语言再次发布只重译被修改的段落（S12）；站点资源经 `TranslatableResourceChangedEvent` 走同样流程，保存即生效。
   - 开放新语言、批量导入、术语表变化后重译时创建批量任务，限制并发与速率，可暂停、取消、重试（S11）。
   - 源语言下线或进回收站时，`AUTO` 模式的目标语言跟随下线，`MANUAL` 不受影响。单条内容通常 1–5 分钟完成；**AI 引擎故障不影响中文内容的发布**。
6. **质量保障**（5.8）：站点级术语表（可标记“禁止翻译”，相关条目放入提示词；术语变化后可一键重译相关的 `MACHINE` 条目）；站点 × 目标语言的风格指南；占位保护（型号、数字与单位、URL、邮箱、`content://` 引用、占位标签原样保留）；自动校验（占位标签、数字、禁止翻译的术语、术语译法、长度上限、无残留中文、合法 JSON 且单元 ID 一一对应）。校验失败自动重试一次，仍失败则标记 `NEEDS_REVIEW`，所在本地化不自动发布。翻译编辑器按段并排显示，可修订（`HUMAN`）、确认（`REVIEWED`）、单段重译。**法律页面的机器译文必须人工审校后发布**。SEO 健康检查增加“关键页面的机器译文未经审校”（INFO，14.9）。
7. **引擎接入**（5.9）：后端定义端口 `TranslationEngine`，infrastructure 提供适配器；**默认适配器使用 OpenAI 兼容的 Chat Completions 接口**（`POST {baseUrl}/chat/completions`），可配置 base URL、API Key、模型名、温度（默认 0.2）、单次请求上限、超时、速率上限、结构化输出能力与单价。用 Spring 的 HTTP 客户端直接调用，**不绑定厂商 SDK**；切换服务商只改配置。要求模型返回 `{"items":[{"id":"…","text":"…"}]}`，服务商支持时使用 `response_format`。提示词前缀固定（系统提示词 + 风格指南 + 本批相关术语），待翻译单元在后。429 与 5xx 按退避重试（尊重 `Retry-After`），最多 3 次；可配置**备用引擎**，主引擎持续失败时切换。引擎配置保存在 `trn_engine`，API Key 加密存储（26.6）。
8. **用量与成本**（5.10）：记录每次调用的输入、输出 token 与耗时，按单价估算费用，按天汇总到 `trn_usage_daily`；指标包括翻译记忆命中率、引擎错误率与延迟、待处理单元数、每日费用；**月度预算上限**达到 80% 告警，达到 100% 暂停批量任务（实时任务可配置是否继续）。
9. **询盘按需翻译**（5.7、17.10）：销售在询盘详情页点击“翻译为中文”，inquiry 调用 translation 在 `platform-api` 中的公开服务接口翻译留言，并把译文保存到 `inq_inquiry.message_translated`（记录 `message_translated_at`）；再次查看不重复调用；站点可关闭；询盘译文不写入翻译记忆。
10. **安全与隐私**（26.3、26.8）：待翻译文本与译文一律按数据处理（转义输出、不执行、不作为后续提示词的指令）；单元 ID 由系统生成并校验。自动翻译只发送公开的内容与站点资源；AI 服务商纳入处理者清单（ADR-016）。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 人工翻译 + 过期检测（V1.2） | 质量可控 | 1 万产品 × 多语言的成本与周期不可接受；与业主确认的方式不符 | 不采用（保留为 `MANUAL` 模式） |
| 前台渲染时实时翻译 | 无需存储 | 延迟高、按访问量计费、结果不稳定，违反“前台只读快照” | 不采用 |
| 整篇翻译，不用翻译记忆 | 实现简单 | 每次修改都整篇重译，费用高，并冲掉人工修订 | 不采用 |
| 绑定某一家机器翻译或大模型厂商的 SDK | 接入快 | 更换服务商要改代码 | 不采用；统一使用 OpenAI 兼容接口 |
| 接入外部翻译管理系统（TMS） | 功能成熟 | 增加外部系统、数据同步与处理者，与内容内核集成复杂 | 不采用 |
| 所有机器译文都先人工审校再发布 | 质量最高 | 无法达到“5 分钟内生成并发布”（1.5、S1） | 只用于法律页面；其他内容按站点配置 |
| translation 模块 + 段级翻译记忆 + OpenAI 兼容接口 | 同一原文只翻译一次；人工修订优先且不丢失；服务商可替换；异步，不影响中文发布 | 新增模块与流程；质量依赖校验与审校 | 采用 |

## 后果

### 正面

- 编辑只用中文录入一次；开放新语言是配置操作，翻译记忆中已有的原文不调用 AI。
- 修改内容只重译变化的段落，费用随修改量而不是内容总量增长；人工修订永久保留并在全站复用。
- 术语表、风格指南与共用的翻译记忆让全站译法一致。
- 切换服务商只改配置；引擎故障只延迟目标语言，不影响中文内容。

### 负面与代价

- 新增一个模块与一套异步流程，M3 的工作量增加；每种内容类型、每类站点资源都要实现提取与回写（29.2）。
- 机器译文可能有术语或语气错误，自动校验不能发现所有问题，关键页面需要母语人员抽检；法律页面必须人工审校。
- AI 调用产生持续费用，需要预算、告警与用量报表；翻译记忆不设过期，会持续增长。
- `AUTO` 模式的目标语言不能自由编辑，只能按段修订；需要独立内容时改用 `MANUAL` 模式并自行维护。
- 待翻译文本与询盘留言可能包含提示词注入，需要按 26.3 处理；询盘翻译会把个人数据发送给 AI 服务商（ADR-016）。

### 需要遵守的规则

| 规则 | 检查方式 |
|---|---|
| 新增可翻译字段时，在 `TranslatableContentProvider` / `TranslatableResourceProvider` 中登记；组件属性正确标注 `x-translatable` | 完成定义（29.6）；组件 Schema 校验；附录 A 语言规则 |
| 机器翻译不覆盖 `HUMAN` / `REVIEWED` 条目；同一原文不重复调用引擎 | 用假引擎的模块集成测试（28） |
| 占位标签、数字等校验不通过的译文不自动发布 | 用假引擎的模块集成测试（28） |
| 法律页面与 `legal` 模板的机器译文不自动发布 | 模块集成测试；PR 评审 |
| 不引入厂商 SDK；只通过 `TranslationEngine` 端口调用引擎 | PR 评审（依赖变更）；ArchUnit |
| 翻译在事务提交后异步执行，不在发布事务中同步调用 AI；监听器幂等（ADR-003） | PR 评审；模块集成测试（Scenario API） |
| 前台渲染时不调用 AI；前台文案只来自文案键或翻译流程 | PR 评审；附录 A |
| API Key 加密存储，不写入日志与代码仓库 | PR 评审；gitleaks（26.6） |
| 译文与询盘留言按纯文本处理，不作为指令；响应中的单元 ID 必须与请求一一对应 | PR 评审；自动校验（5.8） |
| 询盘译文不写入翻译记忆 | 模块集成测试 |
| 翻译失败积压、达到月度预算 80% 时告警 | 27.4 的告警规则 |
| 端到端行为 | E2E 场景 S1、S11、S12、S13（28） |
