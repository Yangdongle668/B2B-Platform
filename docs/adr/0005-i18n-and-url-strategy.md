# ADR-005：语言策略与 URL

| 项 | 内容 |
|---|---|
| 状态 | Accepted（已确认） |
| 日期 | 2026-10-06 |
| 决策者 | 业主、架构负责人 |
| 相关章节 | 0.4（A2、A3）、0.5、1.3（S1、S11）、2.4、2.5、5.1、5.4、6.1、6.2、11.6、13.2、13.3、14.3、14.4、16.4、19、21.7、22.5、24.2、32（Q2） |
| 相关 ADR | ADR-004、ADR-008、ADR-009、ADR-013、ADR-017 |

## 背景

- 目标市场为欧盟、英国与北美（A2）；后台用户（编辑、销售等）主要在中国大陆（A3）。
- V1.2 的方案：默认语言为英语且不加 URL 前缀，其他语言加前缀；`x-default` 指向英语；后台界面支持中文与英文；其他语言由人工翻译。
- V1.3 业主确认（0.5）：
  1. 管理后台的界面语言只用简体中文；
  2. 前台网站先只显示简体中文；其他语言通过 AI 翻译生成，翻译一次并存储，相同原文不再翻译（ADR-017）。
- 约束：
  - 任何内容变化都不得静默丢失 URL（P6）；以后开放英语、或把默认语言从中文改为英语时，不应让已有 URL 失效或产生大批重定向；
  - 搜索引擎需要每种语言有独立、稳定的 URL 与正确的 hreflang；按 `Accept-Language` 自动跳转对爬虫不友好（5.4）。

## 决策

| 项 | 决策 |
|---|---|
| 后台界面语言 | 只提供简体中文：不做语言切换，不引入 vue-i18n，界面文案集中在常量 / 字典文件中（2.4、22.5）；后台错误信息（RFC 9457 的 `title`、`detail`、`errors[].message`）使用中文（24.2）；`module.json`、组件定义、模板定义中的 `name` / `label` 只写中文字符串 |
| 源语言 | 简体中文 `zh-CN`。内容与站点资源只用中文录入；`cnt_content.primary_locale` 即源语言（5.4、6.1） |
| 对外语言 | 前台 V1 只开放 `zh-CN`。其他语言（建议首批 en、de、fr、es、it）由 AI 翻译生成；站点管理员在站点语言设置中把该语言设为“对外公开”即可上线，不需要改代码（5.4、S11）。语言切换器只列出对外公开的语言（16.4） |
| URL 前缀 | **全部语言都带前缀**：`/zh/…`、`/en/…`、`/de/…`；前缀取自站点语言配置，内容类型的 URL 规则本身不含语言前缀（6.2）。V2 支持每种语言使用独立域名 |
| 根路径 | `/` 以 **302** 跳转到站点“默认对外语言”的首页；固定跳转，不按 `Accept-Language`（5.4、13.2）。用 302 而不用 301，是因为默认对外语言以后可以调整 |
| hreflang | 默认只用语言代码：中文为 `zh`（可配置为 `zh-Hans`），英语 `en`、德语 `de`…；英语只做一个版本，同时服务美国与英国。只有已发布且“对外公开”的语言输出 hreflang（14.4） |
| x-default | 首页指向 `/`（会跳转到默认对外语言）；其他页面指向默认对外语言的版本 |
| canonical | 指向本语言自身，禁止跨语言 canonical（14.4） |
| 不回退 | 内容不跨语言回退：某内容在某语言下没有已发布的本地化（包括译文尚未生成）时，该语言下就不存在这个页面，列表与推荐中也不出现 |
| slug | 中文默认用拼音音译（ICU `Han-Latin; Latin-ASCII`），可手工修改；其他语言的 slug 由译文标题按该语言的音译规则生成，**首次发布后固定**，之后译文变化不自动修改（13.3） |
| 界面文案 | 前台固定文案只写成文案键，由主题提供默认中文文案、站点可以覆盖，作为站点资源翻译到各语言；组件中不得硬编码中文或英文（21.7） |
| 字体与搜索 | 中文使用系统字体栈，不下载中文 Web 字体（11.6）；中文索引使用 Meilisearch 内置的中文分词（19） |
| RTL | 不在 V1 范围；前台样式全部使用 CSS 逻辑属性 |

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| V1.2 方案：默认语言不加前缀，其他语言加前缀 | 默认语言的 URL 较短 | 默认语言从中文改为英语（或反过来）时，大量 URL 改变，需要批量重定向 | 不采用 |
| 根路径按 `Accept-Language` 自动跳转 | 访客直接进入母语页面 | 对爬虫不友好；同一 URL 的内容随请求头变化 | 不采用（可显示语言建议条） |
| 根路径 301 到默认语言 | 永久跳转 | 默认对外语言以后可能调整，301 会被长期缓存 | 不采用，改用 302 |
| 每种语言独立域名 | 本地化信号强 | 域名、证书、CDN 配置成本高，V1 不需要 | V2 可选 |
| 缺少译文时回退显示源语言 | 各语言页面数量一致 | 页面语言混杂；hreflang 与内容不符，形成重复内容 | 不采用 |
| 后台中英双语（vue-i18n） | 可服务非中文用户 | 后台用户都使用中文；每个界面都要维护两套文案 | 不采用；文案集中存放，便于以后扩展 |
| 以英语为源语言录入 | 直接面向目标市场 | 与业主确认的录入方式不符，编辑团队以中文工作 | 不采用 |

## 后果

### 正面

- 开放新语言、调整默认对外语言都不改变任何已有内容的 URL，也不产生重定向。
- 编辑只需用中文录入一次；开放语言是配置操作，不需要改代码。
- hreflang、sitemap、语言切换器来自同一组“已发布且对外公开”的本地化，相互一致。
- 不存在语言混杂的页面。

### 负面与代价

- 所有 URL 都多一级语言前缀；中文 slug 为拼音，可读性有限，多音字需要人工修正。
- V1 前台只开放中文时，面向欧美市场的 SEO 效果要等开放英语等语言后才体现（路线图 M3）。
- 目标语言内容的质量依赖 AI 翻译与人工审校（风险与对策见 ADR-017）。
- 后台以后若要支持其他语言，需要另行改造（文案已集中存放，可以降低成本）。

### 需要遵守的规则

| 规则 | 检查方式 |
|---|---|
| 后台不引入 vue-i18n，不做语言切换；文案集中在常量 / 字典文件中 | PR 评审（依赖变更）；附录 A 语言规则 |
| `module.json`、组件与模板定义中的 `name` / `label` 只写中文字符串 | 组件 Schema 校验（契约测试，28）；PR 评审 |
| 前台组件不硬编码用户可见文案，使用文案键或翻译流程 | PR 评审；附录 A 语言规则 |
| 新增可翻译字段在 `TranslatableContentProvider` / `TranslatableResourceProvider` 中登记 | PR 评审；附录 A 语言规则 |
| URL 规则不含语言前缀；布局文档中不保存 URL | PR 评审；附录 A“严格禁止”第 4 条 |
| 根路径 302、canonical 指向自身、hreflang 互链正确、无重定向链 | SEO 爬取检查 `tools/seo-check`（28） |
| slug 生成与音译规则（含“译文 slug 首次发布后固定”） | 单元测试（URL 规范化，28） |
| 开放语言的端到端行为 | E2E 场景 S1、S11（28） |
| 修改本 ADR 的任何决策（如改为默认语言不加前缀）需要新的 ADR | 29.5 |
