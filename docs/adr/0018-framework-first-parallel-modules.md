# ADR-018：框架先行、契约优先，模块按独立设计文档并行开发

| 项 | 内容 |
|---|---|
| 状态 | Accepted（已确认） |
| 日期 | 2026-10-07 |
| 决策者 | 业主、架构负责人 |
| 相关章节 | 2.1（P1、P3、P8）、3.1–3.8、4.2、4.3、28、29.1–29.7、30、附录 C |
| 相关 ADR | ADR-001、ADR-002、ADR-003、ADR-011 |

## 背景

- 系统设计说明书 30 章按垂直切片（M0–M5）组织里程碑，每个里程碑横跨多个模块，模块之间容易互相等待。
- 系统设计 3.3 已规定所有跨模块契约只放在 `platform-api`（ADR-002），模块之间在编译期互相不可见，这为并行开发提供了结构基础，但契约目前只以表格和示意代码的形式分散在 3.7、4.3、6.4、10.5 等章节，还不足以让各模块直接编码。
- 原计划的单一《领域模型与数据库设计》文档把所有模块的表放在一起，单个模块的开发者需要在一份大文档中查找自己的内容，也不利于按模块分配与评审。
- 业主确认：先写好系统框架，再为每个模块单独编写设计文档，模块彼此独立、可以并行开发。

## 决策

### 1. 三层设计文档

| 层 | 文档 | 内容 |
|---|---|---|
| 系统设计 | `docs/architecture/system-design.md` | 顶层架构约束、需求范围、原则 |
| 平台框架 | `docs/framework/platform-framework.md` | 工程结构、**全部跨模块契约的完整签名**（服务接口、扩展点、事件、端口、共享类型）、platform-core 与基础设施、platform-core 数据模型、数据库通用约定、前端框架、测试替身、质量门禁、本地环境、模块设计文档模板、并行开发计划 |
| 模块设计 | `docs/modules/<模块ID>.md`（每个模块一份） | 职责与边界、依赖与契约（只引用框架中的契约）、领域模型、数据模型（表结构与 DDL）、业务流程、接口、后台界面、前台组件、配置、任务、测试、独立开发说明、验收标准 |

原计划的单一《领域模型与数据库设计》不再作为独立文档：通用约定与框架表并入平台框架文档，各模块的表结构与 DDL 并入对应的模块设计文档。

### 2. 框架先行（M0）

M0 交付平台框架：platform-core、platform-api（契约冻结）、`platform-testkit`（每个服务接口的内存实现与契约测试套件）、infrastructure 适配器、application 装配、Admin 外壳、前台渲染框架、共享前端包、CI 门禁与本地开发环境。

### 3. 契约优先、模块并行

- 模块只依赖 `platform-api` 与 `platform-testkit`；在其他模块实现完成前，用测试替身开发与测试，模块之间不互相等待。
- 契约的提供方实现与 testkit 中的替身都必须通过同一套契约测试，保证替身与真实实现行为一致。
- 模块文档不得自行定义跨模块契约；需要新契约或修改契约时，先改平台框架文档并按 ADR 流程评审（29.5），再由框架负责人更新 `platform-api` 与 testkit。
- 集成按系统设计 30 章的里程碑进行：开发并行，验收仍以场景（S1–S13）为准。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 只按垂直切片里程碑推进，不单独冻结契约 | 每个里程碑都能演示完整链路 | 多个模块同时修改、互相等待；契约随实现漂移 | 不采用（保留里程碑作为集成与验收节奏） |
| 单一的《领域模型与数据库设计》+ 模块共享一份接口文档 | 全局视图集中 | 文档过大，难以按模块分配与评审；模块开发者需要在多份大文档中查找 | 不采用 |
| 各模块自行定义并发布自己的接口 | 模块自主 | 与 ADR-002“契约只在 platform-api”冲突；接口风格不一致，难以集中评审 | 不采用 |
| 框架先行 + 契约冻结 + 模块文档独立 + 测试替身 | 模块可以并行开发；职责清晰；评审按模块进行 | M0 前期投入大；契约变更需要走评审流程 | 采用 |

## 后果

### 正面

- 各模块可以由不同的人或 AI 会话同时开发，开发者只需阅读平台框架文档与本模块文档。
- 契约集中、签名完整，减少集成阶段的返工。
- 模块文档自带数据模型与 DDL，数据库变更按模块评审。

### 负面与代价

- M0 工作量增加：需要先完成契约、测试替身与契约测试，才能全面并行。
- 契约冻结后，新增或修改契约需要评审，响应速度变慢。
- 测试替身需要随契约同步维护。

### 需要遵守的规则

| 规则 | 检查方式 |
|---|---|
| 模块只依赖 platform-api 与 platform-testkit，不依赖其他模块 | Maven 依赖 + ArchUnit + Spring Modulith `verify()`（29.3） |
| 每个服务接口在 testkit 中都有内存实现，且与提供方实现通过同一套契约测试 | CI 中的契约测试任务 |
| 模块文档中出现的契约必须在平台框架文档中存在 | 文档评审；CI 文档检查脚本（引用的接口名必须存在） |
| 契约变更先改平台框架文档并走 ADR 流程 | CODEOWNERS（platform-api、docs/framework） |
| 模块的表结构与 DDL 只在本模块设计文档中维护，与迁移脚本一致 | 文档评审；DDL 在 MySQL 8.4 上执行验证 |
