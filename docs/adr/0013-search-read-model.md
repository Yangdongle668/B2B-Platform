# ADR-013：Meilisearch 作为搜索读模型

## 背景

- 前台需要两种查询能力（19）：站内搜索（按标题、型号、摘要、分类、正文检索，型号要精确）；分类落地页的产品分面筛选（按分类与产品属性 `attr.*` 组合筛选并统计数量）。
- 模块只访问自己的表，不允许跨模块 JOIN（3.3 R5、ADR-002）。产品属性在 product 模块，分类在 taxonomy 模块，发布状态与投影在 content 模块，用 MySQL 直接实现分面查询需要跨模块拼装。
- 前台只读取发布态数据（P4）；发布时生成快照与投影（ADR-004）。
- 规模（A4）：单站 1 万产品 × 最多 10 种语言、5 千篇文章；站内搜索限流 60 次 / 分钟 / IP（26.4）。
- 多语言：每种语言的分词、同义词不同；V1.3 起源语言为简体中文，中文需要分词（5.4、ADR-005）。
- 团队 2–6 人（A6），基础设施要尽量少、易运维；源站与数据位于欧盟（ADR-015）。

## 决策

1. **Meilisearch 是发布态的读模型，不是数据源**（2.4、19）：数据的唯一来源是 MySQL 中的快照与投影；Meilisearch 可以随时从数据库全量重建，**不需要备份**（27.5）。生产为单节点 + 快照（27.1），内存基线 2 GB（27.6）。
2. **索引划分**：每个站点的每种语言一个索引，名为 `s{site}_{locale}_content`（如 `s1_de_content`），站点与语言天然隔离（5.3）。
3. **文档构建**：各内容类型通过 `SearchDocumentProvider` 扩展点（3.7）在发布时根据快照构建文档，字段为 `id`、`type`、`title`、`summary`、`body_text`（去除标记，≤ 10,000 个字符）、`terms`（ID 与名称）、`attr.*`（分面字段）、`model_nos`、`url`、`cover`、`published_at`。search 模块不读取其他模块的表。
4. **索引配置**（19）：

| 项 | 配置 |
|---|---|
| 搜索字段优先级 | title > model_nos > summary > terms > body_text |
| 拼写容错 | 型号字段关闭 |
| 中文分词 | 使用 Meilisearch 内置的中文分词，不另装插件；索引设置中通过 `localizedAttributes` 显式声明中文（`cmn`），不依赖自动语言识别 |
| 同义词 | 按语言配置 |
| 可筛选 / 可排序 | type、terms、`attr.*` / published_at、sort |

5. **一致性**：search 订阅内容发布、下线、回收站、分类变化、模块启停等事件（4.3），在事务提交后按 ID + 修订号幂等 upsert，丢弃过期事件（4.1、ADR-003）；每晚做一次数量与哈希比对；提供全量重建命令（运维手册见 27.5）。
6. **用途**（19、14.3）：站内搜索页（`noindex`）；分类落地页 SSR 首屏输出无筛选的默认列表，筛选在客户端通过公开搜索接口 `GET /api/public/v1/search` 完成（24.4），URL 同步查询参数，带筛选参数的页面 `noindex, follow`；页面组件通过 `search-query` 数据源使用（10.5）。
7. **降级**：Meilisearch 不可用时，分类列表降级为基于 MySQL 投影的无分面列表，搜索页显示友好的错误提示；健康检查的 readiness 不包含 Meilisearch，其故障只算降级（27.4）。
8. **安全**：前台查询经后端代理，不暴露主密钥；【V2+】使用 Meilisearch 签发的受限搜索令牌让浏览器直连（19）。
9. search 是 L4 模块，可停用（3.2），停用后的事件监听与公开接口按 3.8 处理；其他模块停用时，该模块的内容类型自动从搜索中排除（3.8）。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| MySQL 全文索引 + 跨表查询 | 不增加组件 | 违反“不跨模块 JOIN”（R5）；分面统计、拼写容错、多语言分词与排序能力弱 | 不采用（只作为降级列表） |
| Elasticsearch / OpenSearch | 功能最全，生态成熟 | 运维与内存成本高，对 A4 的规模与 2–6 人团队过重 | 不采用 |
| 托管搜索服务（SaaS） | 免运维 | 内容数据交给又一个第三方处理，需要评估数据区域（ADR-015）；费用随请求量增长 | 不采用 |
| 把 Meilisearch 当作主存储 | 少一份数据 | 无法保证与发布状态一致，丢失后不能恢复 | 不采用 |
| Meilisearch 作为可重建的发布态读模型 | 开箱即用的多语言搜索、分面、容错；单进程，运维简单；与模块表解耦 | 多一个组件；最终一致；单节点无高可用 | 采用 |

## 后果

### 正面

- 搜索与分面不需要跨模块 JOIN，各模块只负责提供搜索文档，边界清晰。
- 索引可以随时重建，不需要备份；故障只降级，不影响页面访问与发布。
- 中文与各目标语言使用同一套机制，开放新语言时只需新建该语言的索引（文档随译文发布写入）。

### 负面与代价

- 多运维一个组件：版本升级或索引设置变更时，可能需要重建索引。
- 最终一致：发布后索引在 60 秒内更新（1.5），期间搜索结果可能是旧的。
- 单节点没有高可用；故障期间分类页没有分面筛选（31）。
- 索引数量 = 站点数 × 语言数，内存占用随语言增加而增长，需要按 27.6 的基线监控。
- 每种新内容类型都要实现 `SearchDocumentProvider`（29.2）。
- 中文分词效果取决于内置分词器，专业术语可能需要靠同义词补充。

### 需要遵守的规则

| 规则 | 检查方式 |
|---|---|
| 搜索文档只来自快照（发布态），不读取草稿 | PR 评审；模块集成测试（Testcontainers 中的 Meilisearch，28） |
| search 模块只通过 `SearchDocumentProvider` 获取文档，不访问其他模块的表 | ArchUnit；SQL 表前缀扫描（29.3） |
| 索引写入幂等（ID + 修订号），丢弃过期事件 | 模块集成测试（Scenario API） |
| 查询只访问当前站点、当前语言的索引 | 站点隔离测试（28） |
| 主密钥只保存在后端（环境变量或密钥管理服务），前台不直连 | PR 评审；gitleaks（26.6） |
| 不得把 Meilisearch 作为任何业务数据的唯一来源；任何功能在它不可用时都要有降级 | PR 评审 |
| 新内容类型实现 `SearchDocumentProvider` | 完成定义（29.6） |
| 索引设置（字段、分词、同义词）变更后执行重建，并写入运维手册 | 运维手册（27.5） |
