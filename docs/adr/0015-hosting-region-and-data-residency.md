## 背景

- 目标市场为欧盟、英国与北美（A2）；后台用户（编辑、销售）主要在中国大陆（A3）。
- 隐私合规（1.5、ADR-016）：网站处理欧盟、英国访客与询价人的个人数据（询盘联系人、IP、附件、同意记录等，26.8）。V1.2 把“数据驻留欧盟”作为设计决策：数据库、对象存储、备份存放在欧盟；经全球 CDN 的传输、美国服务商的处理、中国大陆员工的访问是否构成跨境传输、需要何种传输机制，由法务确认（1.5、32 章 Q13）。
- 性能（1.5）：HTML TTFB 在 CDN 命中 / 未命中时 ≤ 200 ms / ≤ 800 ms；欧美访客都要覆盖。
- V1.3 业主确认：**云厂商与 CDN 的选择（Q3）、是否需要美国源站（Q15）以及法务事项（Q13）由业主自行负责**，不在系统设计范围内；第 27 章只给出参考拓扑与要求（27 章首）。
- 因此本 ADR 记录的是架构上的建议与系统设计对部署的要求，具体部署方案由业主决定。

## 决策（建议）

1. **源站与数据在欧盟单区域**（27.1）：CDN 以下的全部组件（反向代理、后端、Nuxt、imgproxy、MySQL、Redis、Meilisearch、对象存储）部署在欧盟区域，默认法兰克福，备选阿姆斯特丹、巴黎（2.3）。

| 数据 | 位置 |
|---|---|
| MySQL（托管，主从 + 自动备份） | 欧盟区域 |
| 对象存储（公开桶与私有桶） | 欧盟区域；生产环境复制到另一个欧盟区域（27.5） |
| 数据库备份、对象存储旧版本 | 欧盟区域（27.5） |
| 日志（Loki 或 ELK） | 欧盟区域，保留 30 天（27.4） |
| Redis、Meilisearch | 欧盟区域；不备份（27.5） |

2. **全球 CDN + WAF 覆盖欧美访客**：美国访客由 CDN 边缘节点提供 HTML 与图片（27.1）；CDN 必须支持按 Cache-Tag 清除（2.4、ADR-012）。
3. **第三方服务优先选择欧盟数据区域**（2.4、27.1）：如邮件服务（SES 的欧盟区域、Mailgun EU、Brevo，18）、Sentry（欧盟数据区域）、欧盟区域的托管数据库；统计工具可切换为欧盟托管的 Matomo、Plausible（20.1）。
4. **AI 翻译引擎**（V1.3）：引擎通过 OpenAI 兼容接口接入，服务商只改配置（5.9、ADR-017）。自动翻译只发送公开的内容与站点资源；询盘翻译为按需功能，会发送询盘留言，站点可以关闭。AI 服务商纳入处理者清单，记录数据区域与跨境传输依据（26.8）；选择服务商时同样适用第 3 条。
5. **部署形态**：只有一套生产环境；V1 以 Docker Compose 部署在欧盟单区域的多台主机上（多实例），V2 可迁移到 Kubernetes（2.4、27.1）。
6. **后台访问**：后台静态资源经 CDN 分发，接口响应尽量精简；必要时使用加速线路，其运营方纳入处理者清单评估（22.6、27.1、26.8）。
7. **美国源站**：只有当美国流量远大于欧洲时才评估美东源站，届时需要处理欧盟 → 美国的数据传输（服务商的 EU-US Data Privacy Framework 认证或标准合同条款，由法务确认）；是否需要由业主自行决定（Q15）。

职责划分：

| 事项 | 负责方 |
|---|---|
| 云厂商、CDN、区域的最终选择与实际部署（Q3）；是否需要美国源站（Q15） | 业主 |
| 跨境传输的合规安排（Q13） | 业主 |
| 系统不写死云厂商：对象存储使用 S3 兼容接口、邮件兼容 SMTP / API、CDN 清除通过适配器（2.4、3.1） | 系统设计 |
| 第 27 章的参考拓扑、备份与可观测性要求 | 系统设计（建议） |

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 美国源站（美东） | 北美访客回源更快 | 欧盟个人数据传输到美国，需要传输机制；欧洲访客回源变慢 | 不作为默认；由业主按 Q15 决定 |
| 欧盟 + 美国双源站 | 两地回源都快 | 数据同步、一致性与运维复杂度高，与“单套生产环境”和 2–6 人团队不匹配 | 不采用 |
| 中国大陆源站 | 后台访问快 | 远离目标市场；欧盟个人数据出境到中国 | 不采用 |
| 欧盟源站 + 全球 CDN | 数据留在欧盟；欧美访客由 CDN 边缘提供页面；单区域运维简单 | 美国访客回源与动态请求较慢；中国大陆后台访问慢 | 建议采用 |

## 后果

### 正面

- 数据库、对象存储、备份都在欧盟，满足数据驻留的设计目标，简化 GDPR 合规说明。
- 欧洲访客延迟低；美国访客的页面与图片由 CDN 边缘提供，CDN 命中时 TTFB 达标。
- 单区域、单套生产环境，运维简单。

### 负面与代价

- 美国访客在 CDN 未命中、提交表单、站内搜索时需要跨大西洋回源，延迟较高。
- 中国大陆的后台用户访问欧盟源站延迟高（风险见 31）。
- 第三方服务的选择范围变窄。
- 全球 CDN、美国服务商、AI 服务商与中国大陆员工的访问仍可能构成跨境传输，数据驻留不能单独解决合规问题，需要业主按 Q13 处理。
- 单区域故障时依靠备份与另一欧盟区域的对象存储副本恢复（RTO ≤ 4 小时，1.5）。

### 需要遵守的规则

| 规则 | 检查方式 |
|---|---|
| 新增基础设施组件或第三方服务时，说明数据区域，优先欧盟区域，并更新处理者清单 | ADR 流程（引入新的基础设施依赖须写 ADR，29.5）；上线前合规清单（26.8） |
| 代码中不写死云厂商或区域：存储、邮件、CDN 清除、AI 引擎都通过适配器与配置接入 | PR 评审（3.1、12.5、5.9） |
| 备份与副本只存放在欧盟区域 | 运维手册与恢复演练（27.5） |
| 不向处理者清单以外的第三方发送个人数据；Webhook 载荷默认不含联系人信息（18） | PR 评审；上线前合规清单（26.8） |
| 日志中 PII 脱敏、IP 截断 | PR 评审；27.4 |
| staging 使用脱敏数据（27.2） | 运维流程 |
